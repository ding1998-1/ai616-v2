# 快速会议与会后生成交互实施计划

日期：2026-09-15。状态：计划已制定，本文不代表功能已实现或生产开关已开启。

交接对象：Sol。用户已同意按本方案开展开发；本轮仅交付详细计划。开发时先阅读项目有效规则和现有兼容方案，完成以下任务及验收，不要将本文描述的目标能力当作已实现能力。

## 1. 产品范围

在新建会议的会议类型区域，与普通会议、办公会、专题会并列增加“快速会议”。说明为“一台电脑记录多人讨论，无需手机接入”。先以此类型验证电脑多人录音和会后说话人分离，再评估向其他类型推广。

- 名称和时间自动填写，议题和参会人员可后补；不以虚构议题满足必填校验。
- 主按钮为“创建并进入录音”；后端保存成功后进入会议，由用户点击“开始电脑录音”并授予麦克风权限。
- 第一版不展示 H5 邀请入口；服务器也须校验新建手机录音会话的类型限制，不仅隐藏按钮。
- 会中提供现有实时字幕；会后录音完整保存后异步区分“发言人1/2”，不承诺实时分人。
- 支持会后试听和人工指定姓名，保留匿名结果和修改记录；只影响当前会议的派生身份。
- 快速会议仍须经过纪要人工确认和原有归档权限、材料校验；快速创建不等于降低审核要求。

## 2. 当前代码核查

依据本地代码静态检查，尚未以用户现场会话复现完整问题：

1. `frontend/src/pages/MeetingComplianceWorkflow.jsx` 的 `runStageAction` 在结束时先调用 `stopAndUploadDesktopAudio`，再持久化 `audit`，成功后进入会后页。这一保存顺序应保留。
2. 同文件会后底栏“返回”把 `audit` 映射为 `meeting`，同时调用 `persistStage` 写回“会中记录”。查看上一页实际改变了会议业务状态，用户可能再次遇到结束会议确认。
3. `loadGeneratedMeetingRecords` 捕获错误后返回 `null`；结束分支仍可能显示“纪要与 Word 已自动生成”。成功提示未严格以生成和文档结果为依据。
4. 会后页已有 `generateArchiveRecords`，可以直接调用生成接口；未发现此按钮必须回到字幕页确认的直接跳转。因此需用页面与请求记录确认用户遇到的是返回导致的状态回退、旧状态覆盖还是其他校验。
5. `/api/meetings/{id}/stage` 进入 `audit` 会调度 Whisper。反复结束可能重复触发调度调用，需要验证任务去重。
6. 当前录音完成接口仅以空 `client_id` 判断电脑来源并调度分离，没有快速会议类型限定。生产总开关不能直接开启，应先增加服务端类型白名单。
7. `backend/routes/outcomes.py` 的 GET `/api/meetings/{id}/records` 在 v2 且结果不存在或 force 为真时调用 `generate_records_v2`，不是纯读取。会后页面加载 effect 会调用它。
8. 会后 Whisper 轮询发现有效结果时调用 `generateMeetingRecords({ onlyIfMissing: true })`。仅打开页面也可能触发生成，查看模式必须隔离这条行为。
9. `backend/services/meeting_service.py:update_stage` 将进入 archive 与 `reviewDone=true / archiveDone=true` 绑定。该实现与界面“待归档”存在语义风险，应列为审核项；本次不得顺带重写签字或归档规则。

## 3. 优先修正结束后的交互

目标流程：结束会议 → 保存录音 → 会后整理 → 查看纪要 → 人工确认 → 归档。

- 结束会议只确认一次；保存失败或仍有未上传录音时，在当前步骤展示原因和重试。
- 会后提供“查看录音与字幕”，用抽屉或放大弹窗展示完整底稿；查看、关闭和返回列表均不得写入会议阶段。
- 生成失败留在会后页，展示实际原因和“重试生成”；不要求再次结束会议。
- 区分“录音已保存”“转写处理中”“纪要生成中”“生成失败”“待审核”。等待不显示失败，失败不显示已完成。
- 连点、刷新、重连复用正在执行的任务；确需重新分析时明确告知会产生新版本。
- 将“确认本次纪要”限定为内容审核动作，不作为结束会议或开始生成的重复确认。
- 已确认内容不得被后台完成任务静默覆盖；新结果以待审核版本呈现。
- 修改前先复现现有路径，分别验证前端显示状态、服务端阶段和后台任务状态。

## 4. 实施顺序与隔离

### 已结束会议的查看入口（补充产品要求）

- 会后整理、纪要审核、归档页面均保留明显的“查看会议记录”入口，已归档会议也能按原权限访问。
- 查看页面提供“会议概况 / 议题与讨论 / 录音与字幕 / 纪要与归档材料”导航，覆盖会前、会中和会后已保存内容；资料未保存时明确提示，不假装具备历史快照。
- 顶部固定展示“会议已结束 · 查看模式”，归档后显示“会议已归档 · 查看模式”。显示结束时间须来自已保存数据，不推算或编造。
- 进入历史会议默认查看；会中版面可以复用，但不显示“开始录音”“结束会议”“新增临时议题”等会中操作，也不自动打开麦克风或邀请弹窗。
- 页面使用“查看录音与字幕”“查看议题与讨论”“返回纪要审核”“返回会议列表”等具体文案，避免含糊的“返回”和暗示重新执行的文字。
- 查看导航只切换展示内容，不修改 phase、stage、录音会话或任务状态，不启动生成、分离和 Word 制作任务。须检查现有 GET 请求和页面加载 effect 是否有隐式生成行为，必要时提供纯读取接口。
- “重新生成纪要”等实际修改操作独立放在更多操作中，按现有权限控制；不能与查看按钮混用。需要编辑时显式进入编辑，不通过返回上一页隐式重开会议。
- 保留当前纪要审核位置，查看后关闭或返回即可继续审核。直接链接、刷新和浏览器后退同样保持已结束状态。
- 验收增加：逐个点击全部查看入口，确认无录音启动、无阶段回退、无新生成任务；已归档会议仍可查看完整已保存记录。

### P0-A：消除会后回退和错误提示

检查返回导航、生成状态、任务去重与真实错误映射。只修正已确认问题，保留 PC/H5 上传、ACK、重试、合并和未上传禁止结束的规则。

### P0-B：快速会议创建及录音入口

梳理会议类型存储、枚举、模板推荐、列表筛选和无议题路径；优先沿用现有类型字段，若确需数据库迁移则另行说明。快速会议后端保存失败不得进入看似创建成功的录音页面。开始失败、拒绝麦克风权限和设备断开均提供明确恢复入口。

### P0-C：只对快速会议启用会后分离

触发条件必须同时满足：总开关允许、会议类型为快速会议、来源为电脑、完整录音已验证。调度和重试入口均执行相同校验。旧会议和未知类型默认不进入新分离路径。

使用独立解释器和派生结果；GPU 忙时排队，异常时保留原始录音与转写。先验证长录音及与现有 ASR 并发，再决定灰度模型和配置。既有 3.1 的 60 秒探针通过不代表 Community-1 或全流程验收通过。

### P1：身份审核和后续推广

会后按匿名说话人试听、指定姓名、修正误分组，记录操作人和时间。账号身份代表音频来源账号，不自动证明周围每一句话均由账号本人说出。跨会议自动认人不纳入首版。其他会议类型和 PC/H5 混合去重另行验证。

## 5. 验收要求

- 快速会议：无议题、无 H5 可成功创建并录音；刷新后类型不丢失；不误用正式会议模板。
- 结束：保存成功只结束一次；上传失败可恢复；等待手机上传的原有会议仍被正确拦截。
- 会后：查看字幕不改会议阶段；生成失败原地重试；重复点击不产生重复任务；任务完成不静默覆盖已确认版本。
- 分离：2–4 人真实长录音人工抽查错分、漏分、重叠发言，记录耗时和显存峰值；不凭标签数量宣称准确。
- 隔离：普通会议、办公会、专题会的 PC/H5 不触发新分离；旧会议重试入口同样受限。
- 回退：关闭开关后现有录音、转写、纪要和归档仍可使用，已保存派生结果可读。
- 页面：1440×900 与 1920×1080 登录态实测，内容及按钮无遮挡；检查真实麦克风权限和录音保存。

## 6. 交付边界

每阶段独立验证并记录证据后再部署 44。首轮部署不开全类型分离。实施时以本计划的快速会议限定取代早期“全部电脑录音均可进入分离”的范围；原兼容方案继续约束音频链路隔离。

## 8. 数据与状态契约

### 8.1 快速会议类型

- 建议沿用当前字符串 `type` 字段，新增规范值“快速会议”，前后端分别用统一常量和判断函数，禁止到处按标题模糊匹配。
- `meetingMode` 继续表示现有 normal/major 业务规则；快速会议默认 normal，不另塞入 quick 导致 `meetingMode !== normal` 被误判为重大会议。
- 旧数据缺失类型或含未知类型时不自动迁移为快速会议；不能仅凭“没有手机接入”推断快速会议。
- 开始录音后不允许通过编辑类型绕过资格限制；对快速类型转换至少在服务端拒绝已产生录音的转换请求，返回明确原因。
- 无议题路径必须检查创建按钮禁用条件、后端校验、会中当前议题、计时器、生成纪要、模板及导出；UI 显示“自由讨论”，不自动伪造正式议题记录。

### 8.2 页面展示与会议状态

- 会议是否进行中由服务器持久化事实决定；本地查看面板使用独立状态，例如 `viewMode` 和 `recordSection`，不得通过 `activeStage=meeting` 模拟查看。
- `viewMode=history` 下所有面板均为只读，挂载组件不申请麦克风、不发写请求、不改变阶段。
- `viewMode=workflow` 允许原有权限内的审核及显式生成动作；不要为了只读查看而禁用正常审核流程。
- 从历史查看返回时恢复之前审核页的筛选、滚动位置和当前项。URL 中的查看参数只能改变视图，不能改变业务状态。
- 正式重新开会不在此次范围；查看原会中页面不能充当重新开会入口。

### 8.3 结束与任务状态

| 状态 | 展示 | 允许动作 |
| --- | --- | --- |
| 正在录音 | 正在录音、时长、麦克风来源 | 停止录音、结束会议 |
| 正在保存 | 正在保存录音，请稍候 | 不重复提交结束；失败后重试保存 |
| 上传未完成 | 明确列出未完成来源及原因 | 留在当前页等待或重试，保留原门槛 |
| 会议已结束、任务排队 | 会议已结束，正在准备纪要 | 查看已保存记录、返回列表 |
| 转写/生成执行中 | 展示实际执行步骤，无伪造百分比 | 查看、离开、刷新后恢复 |
| 任务失败 | 具体失败步骤和可理解原因 | 原地重试对应步骤，不再次结束会议 |
| 已生成 | 纪要待审核 | 查看、审核；更多菜单内重新分析 |
| 已确认/已归档 | 展示实际业务状态 | 按权限查看，修改动作独立 |

停止录音、保存录音、结束会议、生成纪要四者要分清成功边界。录音已停止但保存失败时，提示“录音已停止，保存失败”，不能继续显示正在录音或宣称会议已结束。没有录音也没有转写时提示“暂无可生成内容”，不伪报 AI 故障。

## 9. 逐项开发任务与完成标准

### T01：复现并记录问题

建立测试会议，记录结束前后、返回查看、点击生成时的请求、会议阶段、任务编号。重点确认浏览器返回与界面返回是否都写阶段。先完成现状记录，再改实现。

完成标准：能区分已确认的代码缺陷与尚未复现的线上症状；不将本地静态检查写成线上复现成功。

### T02：增加真正只读的记录接口

优先新增显式纯读取接口或显式只读参数，供查看模式使用；沿用鉴权和权限。先保留旧 GET 的兼容行为，避免其他调用方突然失去生成能力。纯读取返回已有内容、缺失标记及已存在任务状态，空结果不触发分析。审查 `get_records` 内部及关联读取是否会更新业务数据，缺内容时返回空状态。

若决定将旧 GET 全面改成纯读取，必须列全调用方并将所有必要生成动作迁移至显式 POST，作为独立变更验收，不能只修改一端。

完成标准：对有结果、无结果、失败结果、已归档四种会议重复读取，生成调用次数为零、任务数和会议业务内容不变（正常访问日志除外）。

### T03：只读查看 UI 与导航

在会后概览区放置文字按钮“查看会议记录”，不要隐藏在图标或更多菜单。打开大尺寸抽屉或弹窗，顶部会议名称和查看状态固定，内部各分区可切换且滚动可达。录音可以播放，字幕可搜索和筛选；没有资料显示空状态。查看模式复用只读展示组件，不直接挂载带录音或生成 effect 的完整会中工作区。

完成标准：用户不用理解阶段号即可找到历史内容；查看及关闭不改变 phase；1440×900 下关闭、导航、播放和返回操作可达。

### T04：结束与生成流程收敛

保留当前上传完整性校验。在执行期间锁定结束动作；服务端同一已完成阶段的重复请求返回现有状态并避免重复事件/后处理调度。失败状态在原位恢复，不使用泛化成功提示。

明确唯一的初次生成触发责任：结束成功后由显式工作流调用生成，或服务器按既有调度统一管理，二选一并记录调用链。浏览器轮询仅负责显示状态。若保留会后转写完成后的升级生成，必须由稳定任务键去重，并保护已确认版本。

完成标准：连点两次、刷新、离开后返回、网络断开后重试都不需要回到字幕页再次结束；Word 制作失败不抹掉成功纪要，也不声称 Word 成功。

### T05：快速会议入口与服务端规则

增加类型选项、说明文案和适配布局。后端保存成功后进入录音准备；确认麦克风权限后才展示正在录音。允许议题为空并覆盖空议题展示。快速会议不弹二维码；服务器对新的 H5 start/join/resume 执行类型限制。

手机限制只能拒绝新会话，不得阻断已接受会话的分片、ACK、重试、完成或遗留录音的恢复上传；已有会议仍按原规则运行。

完成标准：无 H5、无参会人、无议题创建后能完成一次真实电脑录音，刷新和重新进入不变成普通/重大会议；普通会议创建要求仍符合原逻辑。

### T06：分离资格与多录音可靠性

在服务层集中判断资格，完成上传的新结果和复用结果、手工重试均使用它。任务需关联可信的录音事件，不能只看客户端传来的路径或类型。

当前任务和状态按 meeting_id 保存，只能保留一个当前任务/结果；须处理同一会议暂停后续录、多段完成和第二段到达时第一段仍在执行的情况。推荐按录音事件/指纹保存每段派生结果和任务，再聚合会议状态，保证没有录音被静默跳过。

不同录音里的 SPEAKER_00 不一定是同一个人。未验证跨段匹配前，不得合并为同一实名：使用全会唯一匿名标识，保留录音来源，允许人工确认。时间戳必须对应各自录音，不能将第二段局部时间直接对齐第一段或会议总时间。

完成标准：总开关开启时仍只处理快速会议；连续两段和重复完成均得到正确任务/结果；失败、超时、重启可恢复或明确标记可重试，录音完成接口不等待分离。

### T07：会后姓名确认

按匿名说话人展示代表片段、播放入口及“指定姓名”，可从本场参会人选取或输入。确认前说明影响的本场片段范围；批量改名写入派生映射，保留原标签、操作者和时间。不得仅调用现有单条转写改名接口就宣称全场身份确认已完成。

确认、撤销及误分组修正应有权限与日志。原始声纹分组与文字转写证据保留；跨会议自动实名不实现。档案材料使用哪个已确认身份版本必须明确。

完成标准：指定姓名可持久化、刷新后保留、其他会议不变、H5原身份不被覆盖。若 T07 未完成，允许先验收匿名分离，但不得把整项功能标为交付完成。
