# 8002 优雅停机修复与验收标准

## 问题结论

生产环境 `ai-compliance.service` 停止超时 15 秒后被 systemd 强制发送
`SIGKILL`。8002 当前运行入口是拆分后的 `backend.main:app`，不是旧版
`backend_full.py`。风险来自三个退出边界：

1. Uvicorn 未设置有界的 graceful shutdown，WebSocket 或长请求可能持续阻塞。
2. LLM 专用线程池使用 `shutdown(wait=True)`，单个阻塞请求会无限延长退出。
3. Whisper 终审后台任务没有统一停机入口，退出时可能仍在合并或转写。

## 修复约束

- 收到停机信号后，不再接受无限期清理。
- Uvicorn 最多等待 6 秒完成在途请求，超时后取消连接任务。
- LLM HTTP 客户端先关闭，线程池只取消未开始任务，不等待不可中断任务。
- Whisper 任务在应用停机时统一取消，并把未完成状态记录为 `interrupted`，允许重启后重新调度。
- 迁移线程池只负责启动期工作；进入服务阶段前即关闭，避免退出期再次等待。
- 不修改 8091、8092，更不触碰 GPU0。

## 生产验收

- 连续三次重启 8002，每次在 12 秒内完成。
- journal 中不得再出现 `State 'stop-sigterm' timed out` 或 `Killing process`。
- 重启后 `/health` 返回 `status=ok`，数据库查询正常。
- 保持 WebSocket 连接时重启，仍能在超时边界内退出。
- Whisper/LLM 后台工作存在时重启，8002 不被 `SIGKILL`；未完成任务状态可识别、可重试。
- 8091、8092 PID 与 GPU0 工作负载不因本次修改被主动重启。
