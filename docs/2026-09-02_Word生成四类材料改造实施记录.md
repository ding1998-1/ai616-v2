# AI 会议系统 2.0 Word 生成四类材料改造实施记录

## 本次实施范围

依据《AI会议系统2.0_Word生成改造完整指导》，本次先完成不涉及数据库迁移的 P0 收口：

1. 同一次生成固定同一份数据快照，同时产出“会议纪要、会议记录、证据核验附件、完整会议材料”四类 Word。
2. “完整会议材料”按“正式纪要 → 会议记录 → 证据核验附件”分页组合，默认作为前端推荐下载项。
3. 保留旧接口中的 `formal` 文档别名，继续指向完整会议材料，避免旧页面、旧归档记录和已有数据失效。
4. 前端下载弹窗增加材料类型选择；模板选择只影响正式纪要部分，不影响记录和证据的忠实性。
5. 四类文件统一使用会议名称和生成时间命名，不使用 ISO `T` 时间格式作为展示文本。

## 数据边界

- 正式纪要：使用经过校对和证据门禁的结构化纪要、议定事项、风险关注事项和有效待办。
- 会议记录：按原转写顺序保留时间、发言人和校对文本，不把口语记录改写为正式结论。
- 证据核验附件：保留有效转写、剔除行、质量标记、反向索引、异常项和生成参数快照。
- 完整会议材料：仅组合前三者，不重新取数，确保四份文件内容来自同一个生成快照。

## 兼容策略

- 新增文档键：`minutes`、`record`、`evidence`、`complete`。
- 兼容文档键：`formal`，值与 `complete` 相同。
- 下载接口同时接受五个键，旧调用 `/documents/formal` 无需修改即可继续工作。
- 本次不修改数据库 Schema；已有会议在重新生成文档后自动获得四类材料。

## 验收标准

- 后端单元测试验证四个独立 DOCX 均存在且 SHA256 可追溯。
- 完整材料至少有三个 Word section，三个部分均从新页开始。
- 单独会议纪要不包含“会议记录”和原始证据底稿。
- 单独会议记录不包含正式纪要模板内容。
- 前端默认选择“完整会议材料”，可切换并下载其余三类文件。
- 前端生产构建通过；生成样例经 DOCX 渲染后逐页检查无裁切、重叠和缺字。

## 2026-09-03 正式材料质量收口

四类材料架构保持不变，本轮只修复正式交付质量：

1. 正式纪要只接受 `formalSummary`，禁止回退到 `keyPoints`、证据引句或原始 ASR；缺失时显示“待生成正式纪要表述”。
2. REDUCE 阶段将近义议题聚合为 5～8 个正式主议题，文档层再做保守去重，会议记录仍保留全部过程。
3. `待确认`、`待定`、`未知`、`未明确`、`未指定`、`暂无`、`待补充`、`-`、`--` 统一按空值处理，不进入正式待办。
4. 会议记录按“同一议题、同一发言人、相邻间隔不超过 5 秒”无损合并，保留起止时间和底层 segment ID。
5. 正式材料中的 ISO 时间统一转为中文日期时间。
6. 导出前检查会议字段缺失及模板/会议性质不一致；默认推荐匹配模板，允许用户明确确认后继续。

验收要求：后端单元测试、前端生产构建、四类 DOCX 生成、DOCX PNG 渲染与人工目视检查全部通过。
