# 2026-09-08 归档确认 UX P0 实施记录

## 目标

把“逐条给 AI 建议盖章”改为异常驱动审核：服务端批量确认证据正常内容，用户只逐条处理需要重点核验的内容，最后由一次“确认本次纪要”完成会议级确认。

## 实施边界

1. 后端统一计算审核汇总、批量确认资格、异常原因和批次审计。
2. 批量接口按提交时的最新会议成果重新计算，不接受前端传入的安全条目 ID。
3. 已确认和已否决内容保持不变，重复请求不重复写人工审核历史。
4. 前端以一个审核弹窗串联汇总、异常集中处理、批量确认和会议确认。
5. 正式 Word 导出前明确显示未确认内容数量；审阅版区分“AI 未生成”与“AI 已生成但未确认”。
6. 保留现有单条审核、证据门禁和人工放行，不修改数据库 Schema、AI Cleanup 主流程或会议总体状态机。

## 实施顺序

1. 增加 review summary、eligibility、batch review API 与审计事件。
2. 收紧 records/confirm：普通确认只在异常归零后完成，不再隐式批量修改条目。
3. 增加前端审核汇总、异常队列、进度和完成后归档引导。
4. 统一业务文案并修正 Word 未确认提示。
5. 运行后端专项测试、前端纯函数测试、生产构建和 9 月 7 日真实会议只读回归。

## 验收重点

- 18 条正常、2 条异常时，用户只处理 2 条异常，再执行 1 次整场确认。
- `unsupported_ai_claim`、证据不足或冲突内容不能进入普通批量确认。
- 批量审核写入同一个 `batchId`，并记录操作人、时间、确认数与跳过数。
- 并发变化按提交时最新状态返回为跳过项，前端直接进入异常队列。
- 正式 Word 不再把“已有 AI 建议但未确认”描述为“待生成”。
