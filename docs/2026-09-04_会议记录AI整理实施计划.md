# 会议记录 AI 整理实施计划

## 目标

按《AI会议系统2.0 会议记录AI整理改造完整实施方案》重构会议记录生成链路。原始转写继续作为不可变证据层，会议记录改为独立 AI 忠实整理层，正式纪要继续执行“昇晟会议 AI 提炼 + 人工支持”。

## 实施范围

1. 新增独立 `MeetingRecordCleanupService`，不复用纪要、决议、风险和待办 Prompt。
2. 原始转写按 180 秒、4000 字、120 个 segment 三个硬阈值安全分块，并识别文件与背景媒体边界。
3. AI 输出统一保存到 `_recordParagraphs`，保留时间、类型和 `sourceSegmentIds`。
4. Word 会议记录只渲染 `_recordParagraphs`；缺失或失败时显示待整理提示，禁止回退打印完整逐字稿。
5. `_chronicleRows` 保持不变，仅用于证据附件和原文反查。
6. 新增历史会议“重新整理会议记录”接口，不重新执行 Whisper。
7. 人工锁定段落在重跑时保留，不被 AI 覆盖。

## 验证范围

1. 单元测试覆盖安全分块、来源 ID 校验、内容类型、失败降级、噪声过滤和 Word 数据源。
2. 使用 44 上“2026年9月1日会议”真实 3545 条终审转写重跑。
3. 检查段落最大 800 字、普通跨度不超过 5 分钟、无超长记录块、证据 ID 可回溯。
4. 生成真实会议记录与完整会议材料，渲染并逐页检查版式和页数。

## 发布策略

先完成本地测试和构建，再备份 44 当前服务后部署；保留旧版回滚目录，不修改原始录音、原始转写和 GPU0 服务。
