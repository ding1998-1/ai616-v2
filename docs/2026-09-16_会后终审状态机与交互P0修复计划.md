# 会后终审状态机与交互 P0 修复计划

## 录屏确认的问题

1. 纪要确认接口把会议阶段写成 `纪要已确认`，但前端没有该阶段映射，刷新详情后回退为 `会中记录`。
2. 用户在确认成功弹窗点击“进入归档”时，实际再次执行结束会议，继而重复触发手机录音完整性门禁。
3. 审核内容已经全部人工确认时，弹窗仍显示“确认 0 项可采用内容”。
4. 页面标题标为“Whisper 终审转写”，列表却可能展示实时字幕或 AI 纪实，数据来源含混。
5. 同一页面同时出现“继续审核、确认纪要、进入归档”等相近操作，完成状态下主操作仍不清晰。

## 状态约束

- 会议阶段只使用 `会前确认`、`会中记录`、`会后终审`、`待归档`、`已归档`。
- `reviewDone` 表示纪要是否完成人工确认，不再创建新的会议阶段。
- 历史数据中的 `纪要已确认` 读取时兼容映射为 `会后终审 + reviewDone=true`。
- 确认纪要后只能留在会后终审或向前进入归档，禁止退回会中记录。

## 页面约束

- 未确认：主操作为“审核并确认纪要”。
- 已确认：次操作为“查看已确认纪要”，主操作为“进入归档”。
- 没有可批量确认项时，不显示“确认 0 项”；尚未完成会议级确认时显示“完成纪要确认”。
- Whisper 区域只展示 Whisper 原始终审分段，并明确模型、完成时间和来源；实时字幕单独标为“会中实时字幕”。
- AI 生成的纪实、摘要和决议不得冒充 Whisper 原文。

## 稳定性边界

- 不修改 H5 MediaRecorder、分片上传、停止合并、Paraformer 实时识别和 Qwen 二次回看。
- 不修改录音文件和既有会议证据。
- 后端阶段兼容、终审读取接口和前端呈现分别验证。
- 构建通过后必须复现“确认纪要 → 进入归档”路径，确认不会再次出现结束会议弹窗。
