## 一、改造目标

将当前“约 1 秒攒包增量识别”升级为：

```text
手机 PCM 16kHz
  → FSMN-VAD（端点检测＋前置回看）
  → Paraformer Streaming（实时 preview）
  → 句尾静音 500–700ms
  → Qwen3-ASR-1.7B（整句 offline 复核）
  → CT-PUNC（final 标点恢复）
  → 保守领域纠错
  → sentenceId 原位替换 preview
  → 保存为议题绑定的正式转写
```

改造必须同时解决：

1. 首字、句尾丢失。
2. 环境声误触发和无声“蹦字”。
3. 实时转写延迟过高。
4. 句尾专有名词、数字和人名错误。
5. preview 与 final 重复显示或顺序错乱。
6. ASR 故障不得影响录音分片、ACK、续传及最终合并。

## 三、原方案必须修正的设计

1. FSMN-VAD 不加载到 8002 的 `ai_compliance` 环境；它应与 FunASR 一起运行在 8091，避免依赖冲突和重复模型内存。
2. 不使用伪造的 VAD `prob` 字段。FSMN-VAD 以端点事件/分段结果驱动状态机，具体返回结构以 FunASR 1.3.14 实测为准。
3. “回看 2 包”定义为当前包之前保留 2 包，再加当前包；不能只保留总计 2 包。
4. 不再使用“连续两包后才开始发送且丢弃第一包”的门控方式；触发语音后必须把前置缓冲一起送入 online/offline。
5. Qwen3-ASR 使用 `context` 注入会议名称、当前议题和限定术语，不使用不存在的通用 `hotwords` 参数。
6. Offline 模型使用服务器现有 1.7B，不写成不存在的 0.6B。
7. 前端需要支持 `sentenceId`，因此不是“前端零改动”。
8. 多个 offline 任务必须按 `sentenceSeq` 有序提交，禁止后一句先返回导致文本乱序。
9. 口头禅不在证据转写层自动删除；原始转写保真，口语润色只用于纪要生成层。
10. 准确率提升百分比只作为目标，必须由固定测试集的 WER/CER 数据证明。

## 四、目标服务结构

### 4.1 8091：Online ASR 服务

职责：

- 加载 `paraformer-zh-streaming`。
- 加载 FSMN-VAD。
- 加载 CT-PUNC，或只在 final 阶段调用。
- 维持现有 `/api/start`、`/api/chunk`、`/api/finish` 协议，减少 8002 改动。
- 输出 session、增量文本、VAD 状态、端点事件和错误信息。

建议参数初值：

- 手机上行包：250ms，约 8000 bytes。
- Online 推理节奏：300–500ms，禁止继续攒到约 1 秒才推理。
- Streaming `chunk_size`：先以模型 README 和 FunASR 1.3.14 实测值为准，候选 `[0, 5, 2]`。
- 句尾静音：初始 600ms。
- 前置回看：500ms。
- 尾部保留：至少 300ms，防止句尾丢字。

### 4.2 8092：Offline ASR 服务

职责：

- 独立加载 Qwen3-ASR-1.7B，设备只允许 `cuda:1`。
- 接收 WAV 或 raw PCM＋采样率。
- 一次处理一条完整句子，返回高精度文本、语言和耗时。
- 使用 `context` 传递：会议名称、当前议题、参会人员、100 个以内的领域术语。
- 超时或异常时返回明确错误，由 8002 使用 online final 降级。

部署要求：

- 新建隔离 Conda 环境，建议名称 `qwen3-asr`，Python 3.12。
- 优先先用官方 transformers backend 验证正确性；通过后再评估 vLLM，不在第一天直接引入 nightly vLLM 风险。
- 新建独立 systemd 服务，禁止与 8091 共进程。
- 健康接口必须同时检查“进程在线”和“模型可完成短音频推理”。

### 4.3 8002：2pass 协调层

职责：

- 保留 H5 WebSocket 协议和鉴权。
- 将 PCM 连续送往 8091，不再在 8002 先粗暴丢弃音频包。
- 根据 8091 端点事件累积完整句子 PCM。
- Online 输出发送 `preview`。
- 句尾调用 8092，得到复核文本后发送 `final`。
- Offline 失败、超时或服务离线时，使用 8091 最终文本，不阻塞下一句和录音。
- final 继续绑定 `meeting_id + agenda_id + participant_id + audio_client_id`。

## 五、协议设计

### 5.1 WebSocket 对前端消息

```json
{
  "type": "preview",
  "sentenceId": "client-session:12",
  "sentenceSeq": 12,
  "text": "本次会议讨论预算调",
  "backend": "paraformer-streaming"
}
```

```json
{
  "type": "final",
  "sentenceId": "client-session:12",
  "sentenceSeq": 12,
  "newText": "本次会议讨论预算调整事项。",
  "onlineText": "本次会议讨论预算调正事项",
  "backend": "qwen3-asr-1.7b",
  "corrected": true
}
```

前端规则：

1. preview 只更新当前临时字幕，不写数据库。
2. final 按 `sentenceId` 原位替换 preview。
3. 同一个 `sentenceId` 只允许提交一次正式转写。
4. final 迟到时按 `sentenceSeq` 排序，不按网络返回时间追加。
5. Offline 失败时 `corrected=false`，仍提交 online final。

### 5.2 8092 转写请求

推荐首版内部接口：

```text
POST /api/transcribe
Content-Type: multipart/form-data

file: sentence.wav
context: 会议名称＋当前议题＋领域词
language: Chinese
sentence_id: ...
```

返回：

```json
{
  "text": "复核后的完整句子。",
  "language": "Chinese",
  "sentence_id": "...",
  "duration_ms": 438
}
```
