# 实时转写与连续录音修复计划

## 生产样本结论

测试会议 `meeting-local-20260828163613` 共持续约 243 秒，服务端收到 84 个
MediaRecorder 分片。除首片外，后续 WebM 分片是同一容器的连续 cluster，不是可独立
解码的完整 WebM。旧合并逻辑使用 ffmpeg concat demuxer，最终错误地产出 2.893 秒
文件并标记成功。按索引原样拼接后再 remux，可恢复 243.25 秒完整录音。

实时转写共生成 30 条 final，其中 11 条只有 1–4 个字，4 条出现英文或日文幻觉；
同一手机还发生 3 次 WebSocket 重连，造成在线上下文清空。

## 修改范围

1. 同一录音会话的连续 WebM 分片先顺序二进制拼接，再由 ffmpeg remux。
2. 合并结果必须通过 ffprobe，并与客户端上报时长校验；明显过短时禁止标记完成。
3. FSMN-VAD 句尾静音由 600ms 调整为 900ms，减少正常停顿被切碎。
4. 2pass 增加中文会议文本质量门：过滤日文、英文句子、重复幻觉和纯口头填充词。
5. 离线复核结果不可信时回退 online；online 同样不可信时不入库。
6. WebSocket 重连时用该会议最近 final 补充离线 context，降低边界重连后的上下文损失。

## 验收

- 84 分片样本恢复为约 243 秒，而不是 2.893 秒。
- 合并结果不足上报时长 80% 时返回错误，不创建虚假完成事件。
- 英文整句、日文假字、重复短语和环境声填充词不进入 final。
- `sentenceId` 顺序与幂等能力保持不变。
- 录音上传、ASR 2pass、H5 构建和 8002 停机回归通过。
