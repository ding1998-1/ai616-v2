## 四、会后阶段与归档下载

### 已修复

- 修复后端写入“纪要已确认”但前端不识别，导致刷新后退回会中的状态不一致。
- 使用 `reviewDone` 表示人工确认，会议仍在规范阶段中流转；历史状态兼容读取。
- 已确认弹窗改为查看，不再出现重复确认或“确认 0 项”。
- Whisper 终审原文、会中实时字幕、AI 生成材料分清来源，避免标题与内容错配。
- “进入归档与下载”打开 `待归档` 工作区，不再重新执行结束会议。
- 打开下载工作区与最终提交 `已归档` 分离：已确认即可进入工作区；正式归档仍执行原有录音、证据与签字门禁，成功前不得设置 `archiveDone`。
- 重复或延迟到达的确认请求不得将待归档、待签署或已归档会议退回审核阶段。
- 会后内容未加载时显示加载状态；失败可重试，不再先误报“请先生成会议记录”。
- 切换会议后，旧请求不能覆盖当前会议快照。

### 真实页面结果

已登录生产页面实际进入上述会议的归档工作区，点击下载内部审阅版。生成接口与文件下载接口均返回 200。会议保留 `待归档`、`reviewDone=true`、`archiveDone=false`，未替用户正式归档。

只读“查看会议记录”可查看录音与字幕，关闭后回到原工作区；查看不等于重新生成或重开会议。

## 五、新建、开始与结束的交互防错

- 创建与阶段提交增加防重复执行和等待状态。
- 新建失败保留表单，取消伪造临时会议后继续录音的行为。
- 新建页补充明确的返回会议列表入口。
- 草稿保存包含手动议题、尚未点击添加的议题文字和讨论输入；保存失败不退出，重开时恢复已保存议题。
- 开始会议等待后端确认后再推进，不把开始会议误提示为麦克风或声纹已经启动。
- 结束流程明确电脑停止保存与手机自行停止保存的区别；失败保持原阶段。
- 强制结束后的提示不再声称所有音频已保存完成。
- 归档提交失败保留工作区，不提前显示成功或生成完成。
